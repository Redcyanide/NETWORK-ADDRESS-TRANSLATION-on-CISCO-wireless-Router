# Packet Tracer – Examine NAT on a Wireless Router

## Overview

This Cisco Packet Tracer lab demonstrates how **Network Address Translation (NAT)** allows devices using private IP addresses on an internal network to communicate with an external network.

The lab examines:

- NAT configuration on a wireless router
- DHCP address assignment to internal hosts
- Private and public IP addressing
- NAT translation of source IP addresses
- HTTP traffic crossing the network
- Packet headers before and after NAT translation
- Traffic analysis using Cisco Packet Tracer Simulation Mode

## Objectives

- Examine the NAT configuration of a wireless router.
- Configure PCs to obtain IP addresses automatically using DHCP.
- Identify private and public IP addresses.
- Observe HTTP traffic between an internal PC and an external web server.
- Examine packet headers before and after NAT translation.
- Observe how NAT changes the source IP address as traffic leaves the internal network.

## Network Topology

The topology consists of:

- 1 Wireless Router
- 4 PCs
- 1 External Web Server
- Ethernet connections between the PCs and wireless router
- An external network connection represented by the wireless router's Internet interface

## Part 1 – Examine the External Network Configuration

A PC was connected to the wireless router and configured to obtain its network information through DHCP.

The PC's default gateway was identified and used to access the wireless router's web-based configuration interface.

The router's Internet/WAN connection was then examined to identify the address assigned to its Internet interface.

### Key Observation

The address assigned to the router's Internet interface represents its connection to the external network.

**Question:** Is this a private or public address?

**Answer:** The Internet/WAN address is a **public IP address** in the context of this lab.

## Part 2 – Examine the Internal Network Configuration

The wireless router's Local Network configuration was examined.

The internal LAN address and DHCP server configuration were inspected, including the range of addresses available to connected hosts.

### Key Observation

The internal network uses **private IPv4 addresses**.

These addresses are intended for use within local networks and are not directly routable across the public Internet.

## Part 3 – Configure PCs Using DHCP

Three additional PCs were connected to the wireless router.

All four PCs were configured to obtain their network configuration automatically using DHCP.

The assigned network information was verified using:

```text
ipconfig /all
```

The PCs received private IP addresses from the wireless router's DHCP server.

The default gateway provided by DHCP was the wireless router's internal LAN address.

## Part 4 – Observe NAT Translation

Packet Tracer Simulation Mode was used to observe HTTP traffic generated by an internal PC and sent toward the external web server:

```text
ciscolearn.nat.com
```

A Complex PDU was created using:

- Application: HTTP
- Source Port: 1000
- Destination: ciscolearn.nat.com
- Transmission: Periodic
- Interval: 120 seconds

The simulation was then played to observe the packet as it traveled from the internal network toward the external network.

## Part 5 – Examine Packet Headers

The packet headers were examined at different points in the network.

The most important observation was the change in the **source IP address** as the packet passed through the wireless router.

### Before NAT

The packet leaving the internal PC contains:

```text
Source IP:      Private IP address
Destination IP: External server IP address
```

### After NAT

After passing through the wireless router:

```text
Source IP:      Router's public IP address
Destination IP: External server IP address
```

The wireless router translates the private source address into its public address before forwarding the traffic toward the external network.

## NAT Concept Demonstrated

The basic process observed in this lab can be represented as:

```text
Internal PC
Private IP
    │
    │ HTTP packet
    ▼
Wireless Router
    │
    │ NAT translation
    │
    ▼
Public IP
    │
    │ HTTP packet
    ▼
External Web Server
```

NAT allows multiple devices on a private network to communicate with external networks while using private IP addresses internally.

## Verification

The following methods were used to verify the configuration and NAT operation:

### DHCP Verification

```text
ipconfig /all
```

This confirmed that the PCs received their network configuration automatically.

### Connectivity and Traffic Verification

Packet Tracer Simulation Mode was used to observe:

- TCP traffic
- HTTP traffic
- Packet movement through the network
- Source and destination IP addresses
- Changes to packet headers caused by NAT

### NAT Verification

The inbound and outbound PDU details were compared to identify the source IP address before and after the packet passed through the wireless router.

## Key Findings

1. The wireless router provides DHCP services to devices on the internal network.
2. Internal PCs receive private IPv4 addresses.
3. The wireless router has an address associated with its external/Internet connection.
4. Private source addresses cannot be directly routed across the public Internet.
5. NAT translates the private source IP address into the router's public IP address.
6. Packet Tracer Simulation Mode makes it possible to observe this translation at the packet level.
7. Examining inbound and outbound PDU details reveals the change in the packet's source IP address.

## Conclusion

This lab demonstrated how NAT enables communication between an internal private network and an external network.

By examining packet headers before and after the wireless router, the source IP address was observed changing from the internal PC's private address to the router's public address.

This provides a practical demonstration of how NAT separates private addressing inside a network from addressing used to communicate with external networks.
